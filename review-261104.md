## 1. 🔴 Blocking

### 1. [x] Shell injection in remote SSH commands (NFR-9) — DONE (`5a54b2e`)
- **Where:** `MutagenMon.Core/Resolution/ConflictFileClient.cs` (`StatAsync`, `GetKindAsync`, `DeleteAsync`).
- **Problem was:** remote paths were interpolated between `'...'` in the command passed to `ssh host <cmd>`; the remote shell re-parses it, so a file name containing `'` broke out (e.g. `a'; rm -rf ~; echo '.txt`), allowing arbitrary commands or a wrong `rm -rf`.
- **Fix applied:** `ShellQuote` (`'` → `'\''`), `BuildStatCommand`/`BuildKindCommand`/`BuildDeleteCommand` (`internal static`, tested), `rm -rf --`, `EnsureSafeRelativePath` guard in `DeleteAsync` (rejects empty, `.`, `/`, any `..` segment; `\` also counts as separator), `--` before server in `RunSshAsync` and before source in `RunScpAsync`. Tests in `ConflictFileClientTests`.
- **Remaining related work:** items 29–31.

### 2. [x] An auto-resolve failure fails the whole poll — DONE (`fc1ac53`)
- **Where:** `MutagenMon.Core/Resolution/AutoResolveEngine.cs` (`TryAutoResolveAsync`), `MutagenMon.Core/Monitoring/SessionMonitorService.cs` (`PollOnceAsync`).
- **Problem was:** `ResolveAsync` could throw (locked file like `report (1).xlsx` open in Excel → `IOException` on `File.Copy`; scp/ssh error; invalid regex → `ArgumentException`). The exception hit the global catch of `PollOnceAsync`: `_history` never written (retry every poll) and `_stateStore.Publish` never called → `LastSuccessfulPollUtc` frozen → icon stale → self-restart after 90 s → infinite loop.
- **Fix applied:** try/catch (excluding `OperationCanceledException`) around `ResolveAsync`; warning logged with session, file, rule, effective winning side and both URLs; failure cached in history as "not resolved" (conflict stays manually resolvable); invalid regex skipped via `IsRuleMatch`; `ConflictAutoResolved` raised outside the try; `ILogger` now a required constructor parameter. Tests in `AutoResolveEngineTests` and `SessionMonitorServiceTests`.
- **Remaining related work:** items 32–36.

## 2. 🟠 Important

### 3. [ ] "Reload config & restart mutagen" does not recreate sessions
- **Where:** `MutagenMon.App/App.xaml.cs` — `ReloadConfig` and `OnReloadReady`.
- **Problem:** `ReloadConfig` disables monitoring, which terminates all sessions. `OnReloadReady` builds a fresh `SessionMonitorService` but never calls `CreateSessionAsync`. Sessions only come back through the FR-13.1 recovery rule after `SessionMaxNoSession`+1 polls (200 by default ≈ 201 s ≈ 3 min 20 s). If the new config has `StartEnabled=false`, they never come back. Same effect after Add/Edit/Delete session (FR-27.5), which go through `ReloadConfig`: the just-created session is terminated then missing for ~3 min. The shipped config (`SessionMaxNoSession: 5`) hides the bug in dev.
- **Impact:** FR-7.1 and FR-33.3 ("recreates each one") not met; sync coverage lost.
- **Suggested fix:** after `newMonitorService.StartAsync`, explicitly recreate every session of the new session list (`CreateSessionAsync`, failure-tolerant, logged). Cleaner option: add `SessionMonitorService.RecreateAllSessionsAsync(CancellationToken)` called on the first poll when a "post-reload" flag is armed. Do the same in the failure branch (old config) before `SetEnabled(true)`.
- **Spec:** FR-7.1 and FR-13.1 in `requirements/01-functional-requirements.md`; FR-27.5 in `requirements/07-session-management-requirements.md`; FR-33.3 in `requirements/08-mutagen-config-editor-requirements.md`. `ReloadConfig` is also called from `MutagenMon.App/StatusWindow.xaml.cs`.
- **Verify:** Core unit test on the new method (one `CreateSessionAsync` per session on first poll; the fake `FakeMutagenCliClient` in `SessionMonitorServiceTests` already records `CreatedSessions`). Manual: Reload with `SessionMaxNoSession=200` → sessions back within seconds; same for Add/Edit/Delete.

### 4. [ ] `OnReloadReady` can leave the app with no tray icon controller
- **Where:** `MutagenMon.App/App.xaml.cs` (`OnReloadReady`), `MutagenMon.App/TrayIconController.cs` (`Tick` calls `Stop()` then `_onReloadReady()`).
- **Problem:** `OnReloadReady` is `async void`. `ResolveLogFilePath(baseDir, newOptions.LogPath)` does `Directory.CreateDirectory` **outside** the validation `try`: an invalid/non-writable `LogPath` throws. Any exception in `StopAsync`, constructors or `StartAsync` also escapes. It reaches `OnDispatcherUnhandledException` (a dialog) but `_trayIconController` is never restarted.
- **Impact:** frozen icon forever, no staleness detection, no self-restart (TIC-10 only checked by the stopped controller); old monitor stays "disabled".
- **Suggested fix:** move the log-path resolution inside the validation `try`, or wrap the whole post-validation body in try/catch; in the catch log an Error, show the dialog, then **always** restore (`SetEnabled(true)` and `BuildAndStartTrayIconController` with the old config).
- **Spec:** `requirements/03-tray-icon-requirements.md` TIC-10; FR-7.x.
- **Verify:** manual — set `LogPath` to a forbidden path (e.g. `C:\Windows\System32\x`), Reload: dialog shown, icon still alive, monitoring resumed.

### 5. [ ] No config validation at load (startup/reload)
- **Where:** `MutagenMon.Core/Configuration/ConfigLoader.cs` (`Load`), `MutagenMon.Core/Resolution/AutoResolveEngine.cs` (choice mapping), validation currently only in `MutagenMon.App/MutagenMonitorConfigEditorView.xaml.cs` (editor tab).
- **Problem:** validation (`'A wins'`/`'B wins'`, compilable regex) exists only in the editor tab; a hand-edited file bypasses it. `rule.Resolve.StartsWith("B wins") ? BWins : AWins` turns any typo ("B win", "B-wins") into "A wins" → overwrites the wrong side (NFR-8). `MutagenPollPeriodMs <= 0` makes `PeriodicTimer` throw in `ExecuteAsync`, stopping the host and causing endless self-restarts. Invalid regex is now skipped at runtime (item 2) but silently from the user's point of view.
- **Suggested fix:** shared `ConfigLoader.Validate(MutagenMonOptions)` returning a list of errors; call it from `Load` (throw `InvalidDataException`, which triggers the existing startup/reload error dialog) and reuse it in the editor. In `AutoResolveEngine`, strict mapping (`"A wins"` / `"B wins"`, otherwise the rule is ignored with a warning).
- **Spec:** `requirements/06-configuration-reference.md`; NFR-8.
- **Verify:** `ConfigLoaderTests` (invalid resolve, invalid regex, poll period 0 → exception); `AutoResolveEngineTests` (unknown resolve → no copy).

### 6. [ ] TIC-9 / FR-6.4 not implemented: infinite retry instead of self-restart
- **Where:** `MutagenMon.App/TrayIconController.cs` (icon recreate logic: `_recreateRetryCount`/recreate on `InvalidOperationException`, `_iconCache.Get` in `IconImageCache`).
- **Problem:** on `InvalidOperationException` the code arms a recreate on every tick with no limit; it never calls `_onSelfRestartNeeded`. Doc 03 (top priority) requires a self-restart. Other exception types (e.g. `FileNotFoundException` for a missing `.ico` in `IconImageCache.Get`) bubble up to the dispatcher on every tick.
- **Impact:** if recreation fails durably (e.g. explorer.exe killed), no icon and no recovery; undocumented divergence on requirement #1.
- **Suggested fix:** either cap the retries (e.g. 30 ticks) then call `_onSelfRestartNeeded()`, or, if the retry is intentional, document the deviation in `03` §6/§7 (**decision for the user**, see section 8). In both cases also catch `Exception` (not `OperationCanceledException`) around `_iconCache.Get` to avoid a MessageBox flood.
- **Verify:** manual (kill `explorer.exe` while the app runs); if the logic is extracted, unit-test the counter.

## 3. 🟡 Minor

### 7. [ ] Child processes never killed on cancel or hang; no timeout on `mutagen sync list`
`MutagenMon.Core/Mutagen/MutagenCliClient.cs` (the four process runners) and `ConflictFileClient.cs` (`RunSshAsync`, `RunScpAsync`): `WaitForExitAsync(ct)` cancelled leaves the process alive; a blocked `mutagen sync list` has no timeout (only the 90 s self-restart recovers, and it leaves an orphan). **Fix:** `try { ... } catch (OperationCanceledException) { process.Kill(entireProcessTree: true); throw; }` plus a linked timeout (e.g. 30 s) for the poll. See item 32 for the OCE→`TimeoutException` caveat.

### 8. [ ] Reload blocked forever if a session never terminates
`TrayIconController.cs` (reload wait loop, state "Reloading..."): buttons stay disabled indefinitely on a permanent terminate failure. **Fix:** max delay (e.g. 60 s) with a log, then force the reload.

## 6. Follow-ups from the fix reviews

### 29. [ ] Guard the write paths too
`EnsureSafeRelativePath` only protects `DeleteAsync`. Writes (`File.Copy`, scp destination, `CopyLocalDirectoryRecursive`) are not validated: a `relativePath` like `../x` would write outside the endpoint root. Low risk (paths come from mutagen's conflict list) → defence in depth. **Fix:** call it first in `CopyBetweenEndpointsAsync` (also avoids the SSH round trip of `GetKindAsync`) and `PushLocalFileAsync`. Keep `""` allowed for a plain file copy if mutagen syncs a single-file root. **Test:** `CopyBetweenEndpointsAsync(..., "../escape.txt", ...)` expects `ArgumentException` and no file created in the parent of `destinationRoot`.

### 30. [ ] Decide the scp mode (NFR-9, SCP half) — needs the user
`RemoteArg` is unprotected. In legacy scp/rcp mode (OpenSSH < 9.0 default, or an `ScpPath` using that protocol) the path part is re-interpreted by the remote shell: a file named `$(cmd).txt` or `` `id`.txt `` executes a command during A/B wins or visual-merge fetch/push. **Do not** apply `ShellQuote` to scp arguments (in SFTP mode the quotes would be literal and break names containing `'`). **Option A:** add `psi.ArgumentList.Add("-s")` in `RunScpAsync` (forces SFTP; needs OpenSSH ≥ 8.7, breaks older scp) and document it. **Option B:** conditional escaping per mode. **Needs:** the OpenSSH/scp version configured in `ScpPath` on the target machines. **Test:** extract `internal static BuildScpArguments(...)` and assert `-s`; manual: conflict on a remote file named `$(touch pwned).txt` then "A wins", no `pwned` file must appear.

### 31. [ ] Document that `\` is a path separator on every endpoint
`ConflictFileClient.EnsureSafeRelativePath` splits on `/` and `\` even for POSIX endpoints, so a legitimate POSIX file literally named `..\notes` is refused (error shown via `MarkFailed` in `ConflictResolutionWindow`). Conservative on purpose; add a sentence to the XML doc, do not change the logic.

### 32. [ ] Timeouts on scp/ssh copies
No timeout exists in `ConflictFileClient` or the poll: a hung copy freezes the poll and the tray goes stale (FR-6) — the isolation of item 2 covers exceptions, not hangs. **Fix:** linked `CancellationTokenSource` with `CancelAfter`. **Caveat:** the timeout's `OperationCanceledException` would pass both `catch (Exception ex) when (ex is not OperationCanceledException)` filters (`AutoResolveEngine`, `SessionMonitorService.PollOnceAsync`) and stop the service; convert it to `TimeoutException` when the timeout (not the shutdown token) fired.

### 33. [ ] `matchTimeout` on hand-written AutoResolve regexes
`AutoResolveEngine.IsRuleMatch` calls `Regex.IsMatch` without a timeout; a catastrophic pattern would block the poll. Use a `Regex` with a `matchTimeout` and treat `RegexMatchTimeoutException` like an invalid rule (log and skip).

### 34. [ ] Exception thrown by a `ConflictAutoResolved` subscriber
The event is raised outside the try in `AutoResolveEngine.TryAutoResolveAsync`; a throwing subscriber escapes before `_history[key]` is written (in `ApplyToOneAsync`): the poll is interrupted and the copy redone every poll. Current subscriber (`SessionMonitorService` constructor: log + `NotifyAutoResolved`) looks low-risk. **Verify** `NotificationDispatcher.NotifyAutoResolved` and `NotificationQueue` cannot throw; otherwise protect the event call or write the history first.

### 35. [ ] Test for `OperationCanceledException` propagation
No test covers the `when (ex is not OperationCanceledException)` filter in `AutoResolveEngine`. Add to the fake in `AutoResolveEngineTests` a configurable `Exception? ThrowException`, throw `OperationCanceledException`, assert `await Assert.ThrowsAnyAsync<OperationCanceledException>(...)`.

### 36. [ ] `requirements/UserTests.md`: add an FR-10 scenario "auto-resolve fails on a locked file"
Steps: local file open and locked (Excel on Windows) + matching `A wins` rule → warning in `mutagenMon.log`, icon in Conflicts state, file offered in "Resolve conflicts", no "Conflict auto-resolved" toast but the "new conflict" toast present, retry after ≈ `AutoResolveHistoryAgeSeconds` (30 s).

### 37. [ ] Check `~` in `RemoteDirectory`
`SessionMonitorService.BuildEndpoint` accepts URLs like `host:~/path`. Inside `'~/path/x'` the tilde is not expanded, so remote stat/kind/rm return MISSING or delete nothing. Pre-existing behaviour (the old code also quoted the path), not a regression. Check whether real sessions use `~/`; relative-to-home paths (`host:sources/x`) work.

### 38. [ ] Manual test scenarios
- Real SSH endpoint with conflicting files named `it's.txt`, `$(touch pwned).txt`, `` `id`.txt ``, `-rf`: check stat (side panel), A wins, B wins, visual merge (fetch and push); nothing must execute, sizes/mtimes correct.

- Reload with defaults (`SessionMaxNoSession=200`): delay before sessions return (item 3); same for Add/Edit/Delete session.
